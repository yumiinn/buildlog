# Phase 2·3 진행 결과

확인일: 2026-10-26 (한국 시간)

## 완료한 내용

- 당시에는 프로젝트 내부 `database/buildlog.sqlite3`로 회원 기능을 구현했습니다. 이후 Supabase PostgreSQL 연결 준비로 교체했으며 기존 SQLite 파일과 데이터는 보존합니다.
- SQLAlchemy 사용자 모델을 만들고 이메일·닉네임 중복 방지와 닉네임 길이 제약을 적용했습니다.
- 비밀번호는 원문을 저장하지 않고 Argon2 해시로 저장합니다.
- FastAPI에 회원가입, 로그인, 현재 사용자 조회, 본인 닉네임 변경 API를 만들었습니다.
- 로그인하지 않은 요청은 본인 정보 API를 사용할 수 없도록 막았습니다.
- React에 회원가입, 로그인, 내 기록 홈, 계정 설정 화면을 만들었습니다.
- 회원가입·로그인 실패 시 이메일과 닉네임은 유지하고 비밀번호 입력만 지우도록 했습니다.
- 로그인하지 않은 사용자가 내 기록 홈이나 계정 설정 주소로 접근하면 로그인 화면으로 이동합니다.

## 확인한 결과

- 백엔드 자동 테스트 7개가 통과했습니다.
- 이메일·닉네임 중복, 입력 길이, 허용 문자, 비밀번호 해시, 로그인 성공·실패, 인증 없는 접근, 본인 닉네임 변경을 확인했습니다.
- 실제 개발 서버에서 회원가입 → 로그인 → 본인 조회 → 닉네임 변경 API 흐름이 모두 성공했습니다. 확인용 계정은 검사 후 SQLite3에서 제거했습니다.
- SQLite3에 `users` 테이블과 이메일·닉네임 인덱스가 생성되며 파일이 Git에서 제외되는 것을 확인했습니다.
- React 배포 빌드가 성공했습니다.
- Chrome 데스크톱 화면에서 로그인 화면의 글자, 입력칸, 버튼이 정상적으로 보이는 것을 확인했습니다.
- 로그인하지 않은 상태에서 계정 설정 주소로 접근하면 로그인 화면으로 이동하는 것을 확인했습니다.

## 확인하지 못한 내용

- 실제 브라우저에서 입력칸을 직접 조작하는 회원가입·로그인·닉네임 변경 전체 흐름은 자동 API 테스트로 대신했습니다.
- Safari와 Edge 화면 확인은 하지 않았습니다. 여러 브라우저와 360px 화면의 전체 확인은 Phase 12에서 진행합니다.

- 연결 확인 후 다음 단계는 Phase 4입니다. 공부 기록, 할 일, 오류 기록을 저장할 데이터 구조를 만듭니다.
